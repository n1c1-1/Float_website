# astro-float.org

Public website of FLOAT. Astro 5, static output, English at the root, French under `/fr/` with translated addresses. Hosted on Vercel (`vercel.json` sets trailing slashes).

## Run and build

```
npm install
npm run dev       # http://localhost:4321
npm run build     # static site in dist/
npm run preview
```

## Where things live

- `src/i18n/ui.ts`: the routes of every page in both languages (`routes`), the menu (`nav`), the interface strings (`ui`) and the list of blocks in workflow order (`blocks`, with slugs and one-line descriptions). `release` is re-exported from `src/data/release.json`.
- `src/views/`: one component per page, taking a `lang` prop. The files under `src/pages/` only mount them: English at the root, French under `src/pages/fr/`, with the translated folder names (`pourquoi`, `telecharger`, `apprendre`, `projet`, `blocs`).
- `src/layouts/Base.astro`: head, meta (canonical, hreflang, Open Graph, Twitter), menu, language switch, image viewer. A page with no counterpart in the other language sends the switch to that language's home.
- `src/styles/global.css`: all the CSS. `src/components/Figure.astro`: numbered figures.
- `public/`: images, icon, `robots.txt`. The sitemap is generated by `@astrojs/sitemap` (`astro.config.mjs`).

## Add a block page

1. Write the two views `src/views/blocks/<Key>En.astro` and `src/views/blocks/<Key>Fr.astro`, following an existing one (for instance Stacking).
2. Make sure the block has its entry in `blocks` in `src/i18n/ui.ts` (`key` is the file prefix; `slug` gives the address in each language; `desc` is the line shown on the index).

The page, its entry in the side list, the index of the blocks and the link in the home page's methods table appear once both views exist.

## Add an image sheet

The Images section is hidden for now: its pages are in `src/pages/_images/` and `src/pages/fr/_images/` (a leading underscore keeps them out of the build) and it has no entry in `nav`. Rename the two folders back to `images` and restore the `nav` entry to show it again.


Add an entry to `src/data/images.ts` with only what is known: a row with no value is not written. Put the image under `public/images/`. The sheet pages (`/images/<slug>/`, `/fr/images/<slug>/`) and the index are generated.

## Refresh the release data

```
npm run release
```

`scripts/update-release.mjs` reads the latest GitHub release (tag, date, size of `FLOAT-Setup.exe`, SHA-256 printed in the release body) and rewrites `src/data/release.json`. On any failure the file is left as it is and the reason is printed.

## Images, headers, checks

- `node scripts/make-images.mjs` writes the smaller AVIF/WebP copies of the images under `public/images/` (read by `src/components/Picture.astro` as `srcset`; the original stays for the zoom viewer), the social card `public/og-card.jpg` and the app icons. Run it again after adding or changing an image.
- `npm run build` ends with `scripts/sitemap-pairs.mjs`: it rewrites `dist/sitemap-0.xml` from the pages really built, with each language pair written only when the other page exists and points back.
- `vercel.json`: security headers, a Content-Security-Policy (inline scripts and styles allowed, nothing from outside the site), long cache for `/_astro/*` and `/images/*`.
